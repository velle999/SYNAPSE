The desktop speaks, and it keeps your appointments.

Two things happened since 0.2.9.5, and they are the two halves of the same
sentence: the desktop stopped being English, and it stopped needing borrowed
programs for the last few things it still borrowed them for. Every application
SynapseOS ships now answers in **fourteen languages**, and four new ones arrive
— a calendar, a media player, a locked folder, and a disk cleaner.

Underneath both is a third change nobody sees and everybody benefits from:
**every package here now builds on a plain Arch box**, from its own repository,
without this checkout.

174 commits, 50 synui releases, four new applications.

## Fourteen languages, all the way down

English, German, French, Spanish, Portuguese, Italian, Dutch, Polish, Russian,
Japanese, Chinese, Korean, Hindi and Arabic — in the installer, the compositor,
the bar, the welcome guide, the control panel, the lock screen, the file
manager, the package manager, the settings window, the editor, the terminal, the
shell, the calendar, the player, the disk tools, the studio, the arcade, the
sandbox and the vault. **4,046 strings per language across sixteen catalogs**,
which is a little over fifty thousand translations, and 370 more per language in
the installer, which keeps its own.

**Hindi and Arabic actually render.** Their catalogs were finished first, and
what reached the screen was isolated letter forms in reverse order — the
compositor drew text through cairo's toy API, which has no shaper. `text.c` runs
HarfBuzz and FriBidi now, so letters join, conjuncts form, and a right-to-left
line is laid out in the direction it is read. Two languages were complete and
unreadable for four releases, and no amount of translating would have fixed it.

**The language is the first question the image asks.** The bootloader carries a
Language submenu, each entry written in its own language, and the answer
reaches the console keymap, the keyboard layout, the locale, the console font,
the font packs installed and the language `synsh` speaks. The installer does not
ask again twenty minutes later — it reads the answer back.

**⚠ Every machine-readable record stayed English, deliberately.** Every
`--rec` table in this project names its columns in its first row and its
consumers match on the VALUES: `installed === "yes"`, a hud position of
`top-left`, a calendar's `week_start`. Translating one of those turns a window
into a thing that offers a setting no command accepts. Each component's
`i18n_test.sh` proves it by running every offline `--rec` command under a real
foreign locale and diffing the bytes against C.

That rule cost several rounds to learn and each one is worth stating, because
they are the shape of every i18n bug here. `pacman` and every `strerror` print
through gettext, so a suite that greps English output passes on the machine that
wrote it and fails on a Japanese desktop — preflight now refuses a test that
reads a field name gettext rewrites. An id and a label spelled the same need
**two tables**, or a German window offers a position no command accepts. And
once a program is installed, a freshly built copy loads the installed catalog
and answers the desktop's language while the suite asserts English — so the
suites pin the locale they assert in, and a test asserts that the pin is there,
because nothing else can see its absence.

## syn-cal — the calendar

A calendar and schedule planner with three faces: a window, a terminal view and
a command line, over one sync engine.

**It talks to real servers.** CalDAV, Google Calendar and Microsoft 365 over
Graph. Signing in to Google or Microsoft is OAuth 2 with PKCE — the client id
ships, so signing in is two commands and there is no client secret on your disk
to lose. Tokens go in the keyring.

**Your calendar is a folder of files.** One `.ics` per event in a folder per
calendar — the vdir layout `vdirsyncer` and `khal` already write. A private
database would have been less code and would have made this the only program on
the machine that can read your appointments; anything that can read a folder of
`.ics` files can read this one, including a backup, a `grep`, and you.

Make an event from the window or from the command line, see a month at a time
in all three front ends, read an agenda, and — because a calendar you have to
open is a calendar you forget — **double-click a day in the bar's clock** to
put something in it. The desktop calendar shows what is on.

**⚠ Sync is the part that can lose data, so it was built and tested first.**
The store, the identity of an event, and two-way sync across every combination
that can destroy an appointment, before a single pixel of the window existed.

## syn-play — the player

Playlists, shuffle, quick open and history, on top of mpv.

mpv already decodes everything, keeps a playlist, shuffles it, resumes where it
stopped and reads m3u. What it has no place for is SEEING any of that. syn-play
adds exactly those four things and delegates the rest — **every feature asked
mpv first**. Shuffle is mpv's `playlist-shuffle`, and its undo restores the
order files were added in, which mpv keeps and nothing here could have
reconstructed after the fact.

Drop files on it, pin it to the dock, and a folder in the queue is its files —
so shuffle can reach them.

## syn-vault — a folder with a password

`~/Vaults/<name>` while it is open, encrypted at rest, closed when you say so.
There is a window, an applications-menu entry, and a **Vault row in synfiles'
sidebar**, which is where somebody looking for their private files actually
looks.

**⛔ It contains no cryptography and must not.** It makes directories, asks for
a password without echoing it, and runs `gocryptfs`. It derives no key, chooses
no cipher and writes no header. Each of those has a decade of published attacks
behind it, and a file locker that gets one subtly wrong is indistinguishable
from one that got it right.

## syn-clean — disk cleanup and secure delete

`scan` measures ten categories, `clean` removes them, `shred` destroys a file or
folder on purpose, and there is a window. Both of the last two are right-click
entries in synfiles.

Nothing but libc: this walks directories, sums block counts and writes zeroes,
and a library sitting between your files and that code is somebody else's bug on
the delete path.

## Installable on plain Arch

Every in-house PKGBUILD used to read `source=("<name>-0.1.0.tar.gz")` — a file
assembled from the working tree and kept out of the repository — so `makepkg` in
`syn-play/` on a stock Arch box stopped at "Retrieving sources" with nowhere to
look.

**Twenty-two components are published now**, each from its own repository under
`github.com/velle999`, each with a README and topics: the compositor and the
terminal, the applications, the package manager and the security tooling, and
the AI stack. Install the desktop on an Arch machine that has never seen this
ISO.

**⚠ And it is a gate rather than a habit.** A component that is external by
omission is a component nobody notices is unpublishable — which is how synpkg,
the package manager itself, sat that way for forty-three releases while the
check reported twelve components in perfect agreement with themselves. Every
component is now either in the published set or in a table saying why not, and
`preflight.sh` fails on one that is in neither. It also notes when a pkgrel has
moved without a publish, because that release URL carries the pkgrel: the build
still passes here and the first machine that downloads instead of collecting is
the one that fails.

## The login screen

**A fingerprint at the login screen**, which never had one — the lock screen
did, and the greeter did not. It is opt-in, and it comes back out cleanly on a
machine that has no reader enrolled.

The greeter also **says what PAM actually sent it**. It had the words the whole
time and never drew them: the finger prompt was parsed away, so a reader waiting
for a swipe looked like a login screen doing nothing. It looks alive while the
reader is listening now, and "nobody swiped" is no longer reported as the
reader's fault.

## HDR10

`synctl hdr` asks each output whether this machine can be driven in HDR10
without changing what is on screen, and `Shift`+`D` in the display panel drives
the selected monitor in it. `[` and `]` move where SDR white sits.

**⚠ The answer on real hardware was the interesting half-open one.** The
display can be told it is receiving HDR10 — PQ and BT.2020 both yes — while the
CRTC will take none of the three transform shapes that would normally carry it.
The mode is built on the one route the hardware does accept, which is why it
works on a connector where the obvious implementation reports success and shows
you nothing.

## The desktop cube, and desktops per monitor

`anim_workspace = cube` turns the desk about a vertical axis: the desktop you
leave and the one you arrive at as two faces meeting at a right angle. And
workspaces can now be **per monitor** rather than shared, which is a different
question from how the switch looks and is set separately.

## The screen reader, and the assistant's voice

Four bugs in a row, all of the same kind — something that reported success and
did nothing.

The reader's switch **had nothing behind it**: it said On from three surfaces
for four releases and the unit was never packaged. Stopping the reader left it
talking. It read the first syllable of a window title over and over, because a
spinner in a title made every poll look like a focus change. And the
assistant's `voice say` queued the words and exited before saying them, which
made the whole screen reader mute while reporting that it was on.

Dictation also listened to the wrong microphone — it took the first ALSA card,
which on this machine is an empty onboard jack, and "heard nothing" is
indistinguishable from a user who said nothing.

## Everything else

**Right-click Uninstall** in the start menu and the full-screen application
grid. It opens a terminal so `synpkg` can print what it is about to take, ask,
and authenticate — an uninstall is `-Rns` and takes the unneeded dependencies
with it, which is not something to do silently on two clicks. Where an entry did
not come from a package, the menu says so instead of offering.

**Big screen mode has a background** — it follows the desktop's wallpaper —
plus Twitch, YouTube and Spotify tiles, and it answers a television remote:
Back, Menu, Guide, Home, channel up and down and the transport keys an infrared
receiver actually sends, all of which previously did nothing.

**`lsb_release` said "Arch Linux"** on a machine whose os-release has said
SynapseOS since it was installed — it never reads os-release, and the file it
does read is owned by a package that overwrites it on every upgrade.

**An updated machine reports the version it is running.** os-release was
stamped once at ISO build and never rewritten, so a box installed from 0.2.6
media and updated for a month still said 0.2.6 everywhere. Fixed in both
directions: the installer no longer writes the identity through a symlink into
Arch's own file, where the next `filesystem` upgrade would have wiped it.

**synapd speaks llama.cpp's HTTP API** over the model already loaded, on a
socket, with an opt-in TCP port for frontends that need one.

**syntty reflows on resize** — dragging the window narrower no longer changes
what it says — and a resize on the alternate screen no longer aborts it.

`syn-update` learned that chibi is updatable, and stopped installing a printer
driver nobody asked for.
