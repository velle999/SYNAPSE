The image asks which language, and this time everything hears the answer.

0.3.0 shipped fourteen languages across every application on the desk. What it
did not ship was a way for the choice made at the bootloader to reach the
machine that was booting: pick 日本語 and the menu drew a wall of boxes, pick
العربية and it drew Latin letters in the wrong order, and the live desktop that
came up afterwards was in English regardless. The catalogs were right the whole
time. Nothing was carrying them.

Four fixes, in the four places the answer was being dropped.

46 commits.

## The console cannot draw five of them, and now says so

A Linux virtual terminal holds **at most 512 glyphs** and does no text shaping.
Japanese needs thousands; Arabic needs to be shaped. There is no setting, no
font and no package that changes this — the console renders one cell per
character out of a fixed table.

So the text installer keeps **English prose** for Japanese, Chinese, Korean,
Arabic and Hindi, and prints one English line saying why. Everything else about
the choice still applies: the locale, both keyboard halves, the fonts and the
installed system are the ones that were asked for. Cyrillic and Greek fit in
512 glyphs and always did — those languages load `latarcyrheb-sun16` and are
unaffected.

**⚠ And only on a console.** The same installer run from a terminal on the
desktop draws all thirteen; refusing there would have been a second bug in the
opposite direction. The rule is `TERM` as much as the language.

## The live desktop never heard it at all

The live session's compositor is started by `systemctl start synui.service` — a
**unit**, whose environment is the systemd manager's. So `export LANG` in the
installer died with that process, and `/etc/locale.conf` had been read at boot,
minutes before anybody chose. The compositor, the bar, every SynapseOS
application in the session and the graphical installer it autostarts all came up
in English however carefully the language was picked thirty seconds earlier.

`systemctl set-environment LANG=` is the manager's own answer, and it applies to
every unit started after it — which on a live image is all of them. The locale
is generated first if the ISO does not carry it, the desktop keyboard layout
goes into `synuirc` at the same time, and `/etc/environment` is written for the
next login rather than this one.

## The graphical installer speaks the other twelve

The window carried **no catalog at all** — nearly 2,800 lines that read the boot
language to preselect a row and then said everything in English. It was the
remaining half of "the installer was in English", and it is the only installer
here that can draw the five scripts a console cannot.

It still has no catalog of its own, deliberately. `syn-install --strings` prints
the loaded one as `english<TAB>translation` records and the window renders them —
the same arrangement as `--list-disks`, where the script knows and the window
draws. **One catalog serves both installers**, keyed by the English sentence, so
a sentence written once is translated once and appears in both. **597 strings
per language, 549 of them translated** — the rest are product names nobody
translates.

Picking a language on the window's own Region page re-translates it in place,
because the person who most needs that page is the one whose image booted in the
wrong language.

**⚠ Not `qsTr()`.** quickshell installs no translator and cannot reach one, so
`qsTr()` compiles, hands back its own argument and translates nothing — in every
language, forever, while reading in a diff exactly like a marked string.

## Arabic reads the other way

Translating the sentences is not the whole of a right-to-left language. The step
rail counts from the right, the radio dot sits on the right of its label, Back
and Next swap sides, and a wrapped paragraph starts at the right margin. All of
it now follows the language chosen in the window.

**Every card was a fixed pixel width measured against the English label**, with
an anchored row inside — so a longer label did not clip or wrap, it drew
straight over the card beside it. Japanese put half a sentence through its
neighbour. `systemd-boot` was over its own width in English already.

## The application grid was the last English thing on the desktop

Every application ships its own translations inside its `.desktop` file —
`Name[de]`, `Name[pt_BR]`, `Name[sr@latin]`. Firefox alone ships thirty. The
compositor read the plain key, so a German desktop drew German panels around an
**English application grid and English desktop icons**.

The match follows the specification's candidate list exactly: `Name[pt_BR]` is
not offered on a Portuguese desktop, because handing Portugal Brazilian
Portuguese is worse than English. `Icon` and `Exec` are deliberately untouched —
a launcher whose command came from `Exec[de]` would run a different program in
Germany.

## Transparency off made the menus transparent

With **Transparency off**, the start menu became the most see-through surface on
the desktop — the clock legible straight through it — because a bar dialled down
to near-zero opacity took every menu with it whatever the master switch said,
and with transparency off nothing frosts behind them.

The bar is deliberately left as it was: a clear bar with no blur is supported and
works, because its ink comes off the wallpaper. Menus have no such machinery,
which is exactly why the switch exists for them.

## The welcome guide explains layouts

A page for the seven window layouts — tiling, floating, monocle, AI, niri,
spiral and cascade — each named in the order `Super`+`Tab` cycles them, with the
keys that reach the three a keybinding can go straight to and the one that opens
the panel naming all seven. And a last line for the thing that surprises people:
dragging, snapping or maximizing a window takes it out of the layout.

## This desktop, from another machine

`syn-remote` is new: `syn-remote on`, and a VNC viewer somewhere else has the
screen — including when nobody is sitting at this one.

**The usual "Wayland can't do remote desktop" does not apply here.** All three
reasons that is said are about other stacks. GNOME and KDE gate capture behind a
portal that asks a human per session, which rules out unattended access by
design. `xdg-desktop-portal-wlr` implements ScreenCast but **not** RemoteDesktop
— no input injection — which is why portal-based tools can watch a wlroots
desktop and cannot touch it. And nothing exists to connect to before somebody
logs in, which is true here too and is said plainly rather than failing
obscurely.

wayvnc is the server, and it is the wlroots-native one: it captures through
`zwlr_screencopy_manager_v1` and drives the seat through
`zwp_virtual_pointer_manager_v1` and `zwp_virtual_keyboard_manager_v1`. synui
implements all three and hands them to any native client, so no portal is
involved and nothing prompts.

**⛔ A blanked output cannot be captured at all** — measured, not assumed. Once
the idle blank stage has fired, screencopy answers *failed to copy output*: a
viewer gets nothing, with no frame to click on to get out of it, ten minutes
after the last keypress. That single fact is what makes unattended VNC on a
Wayland desktop look broken, and it is what the wrapper is for. A connection
turns the outputs back on and holds a real idle inhibitor until the last viewer
leaves.

**⛔ It binds to loopback.** synnet's base firewall is default-drop on input
*and accepts everything from 10/8, 172.16/12 and 192.168/16* — so a port on
`0.0.0.0` is not "open but firewalled", it is reachable by every device on the
network with no second door to unlock. `syn-remote listen lan` is the deliberate
way to change that and says so. Either way the connection carries TLS and a
password: wayvnc's `enable_auth` requires a certificate, a key and a password
together, so there is no password-without-encryption. Sign in with a generated
twenty-character password, or with your own account through PAM.

**⛔ And a machine that is asleep answers nothing at all.** The screen wake
above is for a screen that has gone dark on a machine that is still running;
a suspended one has no server, no port and nothing listening. `syn-remote
wakeable on` arms the wired card for a magic packet, `syn-remote wake <name>`
sends one to a saved connection — and `syn-remote connect` sends one by itself
when the machine it is opening is not answering, then waits for it, because
nothing acknowledges a magic packet and a viewer handed a sleeping machine just
fails.

Arming it writes two places, and it needs both: NetworkManager **remembers**
the flag and re-applies it every time the connection is activated, which is
what survives a reboot, a replug and a driver that clears it on link-down;
a small helper **applies** it right now, because activating the connection you
are reaching the machine over drops the link underneath you. The state is then
read back off the card rather than out of the setting — the two disagree in
exactly the case that matters, armed now and forgotten at the next boot. ⚠ A
magic packet is a broadcast, so the machine sending it has to be on the same
network; that is a property of Wake-on-LAN, and `wakeable` says so every time
it reports the flag is on.

**And the address it is sent to is now on screen.** A magic packet is addressed
to a hardware address rather than an IP, so waking a machine from another one
means reading a MAC off it first — and until now the only place that existed
was a terminal. Settings ▸ **Network** lists one per interface, beside the
addresses that interface holds, with a single gateway row and a single
nameserver row rather than one of each per interface. Only a wired card can be
woken by a magic packet, and the Wi-Fi row says so instead of leaving somebody
to arm a card that cannot stay associated through a suspend. ⚠ The `fe80::`
link-local address every interface always carries is left out: it is as wide as
a real address and reaches nothing without an interface named beside it.

**And the Speech pane was unreachable.** Adding a Settings pane for this turned
up one that had been missing from the window's own list: `pane_speech` existed
in C, `usage()` named it, and every row on it had a working handler — while
`syn-settings`' sidebar never offered it, so the screen reader and the wake word
were reachable from a terminal and from nowhere else. The person who wants a
screen reader is the person who cannot read the terminal to start one. Both
panes are in the window now, and the suite reads both sources and fails on a
pane either side is missing.

## Wallpapers from wallhaven.cc

`Super`+`Ctrl`+`W` — and a row at the bottom of the wallpaper picker — is a grid
of what is on wallhaven.cc: category chips, sorted by what is popular, paged.
Picking one downloads it to `~/Pictures/Wallpapers` and sets it, so it is an
ordinary local wallpaper from then on: in `Super`+`W`'s list, surviving an
uninstall, with one definition of "make this the wallpaper".

**⛔ Off by default.** It is the second thing on this desktop that talks to the
internet; the weather is the other. The window opens on its own switch, says
what saying yes costs, and asks wallhaven for nothing until the button is
pressed — a keybinding cannot explain itself, having no terminal to explain into.

## AppImages, in synpkg

Install an AppImage and synpkg does the mechanical work: `chmod`, place it,
extract the `.desktop`, rewrite `Exec` to an absolute path, pull three icon sizes
out, name the entry so the dock can pin it, and update two caches. There is an
AppImages tab beside the five sources.

**⛔ It is not a sixth source, and says so in two places.** The repositories, the
AUR, Flathub and BlackArch are all searchable and all upgradable. An AppImage is
neither — no index, mostly no update information, none signed — so `search`
deliberately does not learn about them, and both `install` and `list` say
outright that `updates` will never mention them.

## The television, and the remote

Start ▸ Settings on the big screen, three pages, every row a press of A: which
shelves are drawn, what the Start menu offers, and whether the screen may sleep.
The same rows are on the desktop window's Big screen tab, both drawn from one
table so neither can grow a switch the other refuses.

And a real remote, measured rather than guessed. **Pause is not a media key** —
an MCE remote sends the same code as a keyboard's Pause, never the one
`XF86AudioPause` becomes, so Play worked and Pause did nothing and the two looked
like one feature half finished. **OK, Info and Guide arrive with a key code of
literally zero**, because Qt has no enum for them; Next and Previous have no
keysym at all. All of them answer now.

## Everything else

**The ISO signs itself.** 0.3.0 shipped unsigned: signing needed three things
remembered at once and all three were checked at the end of an hour-long build,
at the exact moment when the cheap way out is to publish anyway. The default is
now signed unless you ask otherwise, the key is named by a committed
fingerprint, and `sign-iso.sh` signs an existing image without a rebuild.

**`syn-update` could not determine update status on any machine.** The updater
was working perfectly and refusing for a good reason, and nothing on screen
carried the reason — which came from a different package's file rename leaving
462 MB of untracked leftovers behind. It says why now, and every escalation goes
through one guarded path, because a `sudo` with no terminal does not refuse; it
prompts, fails, and counts toward locking the account.

**The Windows join instructions named two parts** on an image that has had three
since 0.2.9.5. `copy /b` joins what it is given and exits 0, so the reader got a
short file, a checksum that did not match, and nothing pointing at the join.

**The wallhaven browser opened on every monitor at once**, because an unnamed
output was reading as a request for one window per screen — the same picture on a
single monitor, which is how it shipped twice.
