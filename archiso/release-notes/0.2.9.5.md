The desktop gets an assistant, and stops failing quietly.

The headline is **vibe** — an assistant with a window, a voice, and the run of
the desktop. It opens folders, changes settings, answers questions about this
machine, and runs shell commands you confirm. It talks to the model on your own
hardware by default, and to Claude or OpenAI if you give it a key.

Underneath that is a long run of bugs with one shape: **something that did
nothing, and said nothing about it**. A menu row that launched no program. A
scrollbar that could not be seen. A tool that ran and whose answer never reached
the screen. A boot that sat on a logo for a minute with no sign of life. None of
them printed an error, because in every case the code thought it had succeeded.

Also here: games keep the mouse, files show what is in them, the ISO is signed,
and the lock screen and the login screen finally agree about your monitors.

## The assistant

Press the speech bubble in the bar, or run `vibe gui`. It is the same assistant
in a terminal (`vibe`) as in the window — one conversation loop, one tool set,
one set of confirmations.

**It acts on the desktop.** It opens a folder by the name you use for it —
"downloads", "my pictures", "home" — an application, a web address, or one of
the desktop's own panels. It runs the compositor's actions, and changes settings
like the bar's edge or the wallpaper and applies them live. It reads, writes and
edits files, and runs shell commands inside syn-confine's sandbox.

**Anything that writes asks first.** The line is *does it write*, not *is it
dangerous*: opening a folder or listing a directory happens immediately, while
changing a setting or running a command shows you the command and waits. A
confirmation on harmless things trains the hand to press Enter without reading.

**Plain desktop requests never reach a model at all.** "Open downloads", "what's
in my documents", "lock the screen" are resolved and carried out directly — no
model is loaded, no tokens are generated, and the answer is the tool's own
words. On a machine whose GPU the compositor shares, that is also the difference
between an instant answer and several seconds of the desktop stuttering while
weights load. Measured on "open downloads" with the model in the loop, the
request reached the file manager in **2 runs out of 8**; it is not put to a
model any more.

**It knows what this computer is.** Asked for its specs it reads /proc, the DMI
tables, `lspci` and `nvidia-smi` — CPU, memory, graphics, drives, uptime — and
leaves out any field it cannot read. It used to answer from imagination, in the
confident register of a spec sheet.

**Four ways of behaving, picked per message.** *Ask* answers and touches
nothing. *Agent* answers and acts. *Plan* looks at the machine and writes out
the steps instead of taking them. *Auto* is the default and chooses between them
per message; a question about the world goes to Ask, a question about this
machine goes somewhere with tools.

**Five backends.** The local model through synapd is the default and needs no
account. Ollama and llama.cpp are there for local setups you already run, and
**Claude and OpenAI** for when you want a bigger model — Claude through the
official SDK rather than an OpenAI-compatible shim, so thinking and tool-use
blocks survive. Keys go in your keyring where there is one, and a 0600 file
where there is not.

**Set it up from Settings.** syn-settings has an *Assistant* pane: pick the
backend, store the API key. The key field is masked, and the key never appears
in a command line at any point.

## It listens, and it talks back

The assistant borrows chibi's voice stack. `vibe voice` reads answers aloud and
takes dictation; `vibe wake on` listens for its name and the bar's assistant
button changes while it is listening — a window you cannot see is not a
disclosure that the microphone is open. The switches are in the control panel
and in syn-settings, and the wake words are yours to choose.

The microphone is never opened by an update: the listener ships disabled and
`vibe wake on` is the opt-in.

## It is also a shell

`synsh` answers everyday lines from a table in milliseconds — "what time is it",
"is firefox installed", "open youtube" — and the assistant asks it first. A line
that is genuinely a command is run rather than described, after showing you the
command. It claims whole lines only, so "how do I play music with mpv" still
reaches the model.

## Games keep the mouse

A run of fixes for the same complaint: the pointer leaving the game.

The mouse now stays on the game's screen when the picture does not fill it, when
it is a pixel short of filling it, and when the window is letterboxed inside a
bigger one. Alt-Tab away from a fullscreen X11 game and back, and the game is
still there. Game mode stopped flapping on and off, and pointer smoothing got
two settings of its own — `accel_speed` scales the curve libinput is already on
rather than adding acceleration, so smoothing is now something synui does itself.

MangoHud is no longer loaded into every Vulkan program on the system. `syn game`
turns it on for what you are launching.

## The boot says what it is doing

The splash was a static logo on a screen that could take a minute. It is a logo
sized to your screen, a line naming what is starting, and a progress bar.

It also stopped being stretched. Early boot was running on whatever mode the
firmware handed over — often 4:3, spread across a widescreen panel — because the
graphics driver was not in the initramfs. It is now, so the splash draws at the
resolution your monitor actually has.

## Windows that scroll say so

Every scrolling view on the desktop now shows a scrollbar: the assistant's
chat, the software manager's package list, the file manager, the settings
window, the app grid, the arcade, the installer. A wheel is not a substitute —
without a bar there is nothing saying there is more, how much more, or where in
it you are.

They appear only when there is something to scroll, and stay visible while
there is, rather than fading out exactly when you are deciding whether to reach
for one.

The update window's list stopped escaping its own box: past a certain number of
pending updates the rows drew straight over the heading underneath.

## Files

**Videos have thumbnails.** synfiles could always show one if something else had
made it; now it makes them, and writes them to the shared cache so every other
file manager on the machine gets them too.

**Hovering over a file says what it is** — type, size, dimensions, and for a
folder what it actually costs on disk, measured rather than guessed.

**A file with no themed icon is drawn rather than left blank.**

## The editor

syn-edit's window is modeless: it opens ready to type, with the vim keys still
there in the terminal. It pastes, Backspace joins lines, and there is a document
panel listing what is open with a close button that asks before losing work.

## The lock and login screen

**The login screen arranges your monitors the way the desktop does.** It used to
lay them out in whatever order the connectors came up, which on a desk with a
portrait panel is nothing like your desktop. The arrangement is published by
your own session, because the login screen runs as another account and cannot
read your configuration.

**It also shows your lock screen's background**, and your keyboard layouts — a
password with a character that needs your second layout could not be typed at
the login prompt at all.

**The fingerprint reader stops disappearing.** A locked laptop left alone would
quietly stop offering it after a couple of minutes: the reader timing out looks
identical to a finger that did not match, and the lock screen was counting them
the same way.

**And you can enrol a finger without a terminal** — syn-settings has a
Fingerprint pane that enrols one and says which of the three unavailable states
you are in: no daemon, no reader, or nothing enrolled. Fingerprint support needs
`fprintd`, which is not on the image; `sudo pacman -S fprintd` and the pane and
the lock screen both come alive.

## Releases are signed

The ISO now carries a GPG signature, and the public key is published on
**soslinux.org** rather than in the release. A checksum sitting beside the
download proves the download is not corrupt; it proves nothing about where the
image came from, because whatever could alter one could alter the other.

```
gpg --import synapseos-release-key.asc
gpg --verify SynapseOS-0.2.9.5-x86_64.iso.asc SynapseOS-0.2.9.5-x86_64.iso
```

The key's fingerprint is on the download page. Releases before this one are not
signed.

## HDR on the monitor that has it

Press `Shift`+`D` in the display panel (`Super`+`D`) on a screen that supports
it, and the desktop is driven in HDR10.

The column beside each monitor says which ones can be. **HDR10 ON** is a display
being driven in HDR right now; **HDR10** is one that can be and is not;
**HDR10 (—)** is a panel that claims HDR over a cable or a refresh rate that
will not carry it. Two of the three monitors on a typical desk say nothing at
all there, and that is the honest answer — before this, the same column showed
every 10-bit-capable screen as HDR whether or not it was.

`[` and `]` set where SDR white sits, 203 cd/m² by default. HDR measures
brightness in real units rather than as a fraction of what the panel can do, so
a desktop has to be told where its white goes. It is not a brightness control:
it moves only where ordinary windows sit inside an HDR signal, which is what
decides whether the desktop looks right beside an HDR video or washed out next
to it. Both the mode and the level are remembered per monitor.

The same two controls from a script are `synctl hdr on|off <output>` and
`synctl hdr white <output> <cd/m²>`, with `synctl hdr` on its own reporting what
each screen will accept. Switching it on can fail, and when it does it says so.

**What this is.** The display is told it is receiving HDR10 and the desktop is
mapped into it correctly, with 10-bit colour switched on alongside so dark
gradients do not band. The desktop itself is still drawn in ordinary sRGB, so an
HDR video does not gain highlights it did not have before — that is a different
and much larger piece of work. Night light still warms a screen that is in HDR,
and warms it by the same amount as the screen next to it.

## The desk turns

Switching desktop can now turn the whole desk in three dimensions. The desktop
you are leaving and the one you are arriving at are two faces of a cube meeting
at a right angle, on black, lit so the corner between them reads, pulled back
far enough that the turn fits on the screen you are watching it on. It is under
*Windows → Desktop switch* in the control panel, beside the cross-fade and the
slide, and it wants a longer length than they do — 400 to 600 milliseconds
rather than 140.

It works differently from the other two, and it had to. The fade and the slide
move each window; a cube moves the picture, and the compositor's scene graph can
place a window but cannot turn one in perspective. So the cube takes the frame
instead: it photographs the desktop being left, renders the incoming one live,
and draws both as two surfaces through a shader of its own. The projection is
chosen so that the beginning and end of the turn are pixel-identical to no
animation at all, which is what lets it run on every switch instead of only on
some of them.

If a machine's driver will not give it what it needs, the switch simply is not
animated. Nothing about the cube can cost you the frame.

## Desktops that can differ per monitor

A virtual desktop still spans the whole desk by default, the way KDE and GNOME
do: press Super+2 and every screen changes together, and each window remembers
which monitor it lives on. That is unchanged, and it stays the default.

What is new is *Windows → Desktops span*, which changes who moves rather than
what a desktop is. Set to **Per-monitor**, each screen remembers the desktop it
is showing, and the switch moves only the monitor the focus is on — reference on
one screen, work on the other, and the two no longer travel together.

Two monitors showing the same desktop is a perfectly good state under it, each
drawing its own share, which is what keeps the keys honest: the desktop you ask
for is never one another screen has already claimed, so the bind always does
what it says.

## The screen reader now has a screen reader behind it

The desktop has offered a screen reader from three places — `Super`+`Shift`+`U`,
synui's control panel, and the Settings app — and all three have been reporting
that it was on while nothing was ever announced. The switch wrote its setting
and started a service that was not in the package; the failure was swallowed by
the same line that keeps a machine without systemd from looking broken.

It ships now, and there is a test that fails in the tree if it ever stops
shipping. Two other things came out of the same look: the announcer could not
have found the compositor even with the service present, because a background
service does not inherit the display, and `syn-speak status` reported no speech
engine on machines that speak perfectly well through the assistant's voice.

If you want the reader on a machine with no AI stack installed, it needs a
synthesiser of its own: `synpkg install espeak-ng`.

## Smaller things worth naming

**The desktop stopped writing four gigabytes to the journal.** A debug trace
left switched on system-wide, and a per-token line from the AI daemon, were
together writing about three thousand lines a minute for the length of every
session.

**The task manager reports per-process VRAM on AMD**, which was NVIDIA-only —
the column read "–" on every AMD machine while the header above it cheerfully
reported the card. Its two CPU percentages are one scale now.

**One setting scales the whole desktop** (Super+Ctrl+=).

**An update notifier in the bar**, on a timer you can set or switch off, with a
badge that clears itself.

**The weather left the lock screen** for the bar and the desktop.

**Two terminals ship, not three** — syntty and foot.

**The applications menu draws its icons.** The icon themes the menu's entries
name were never actually required by anything, so a clean install showed a menu
with calendar, bluetooth and a dozen others missing.

**CLI applications launch from every menu.** The launcher had no terminal it
could use for anything marked `Terminal=true`, so those entries did nothing at
all when clicked.

**The assistant has an icon**, and the window titles on the Mac chromes are
centred on the window rather than in the space beside the traffic lights.
