Mostly a bugfix release on 0.2.1's desktop — three things that were supposed to
work already and did not, two of them invisible on a live USB and only broken
once SynapseOS was actually installed. The wallpaper picker also picked up the
work that 0.2.1 shipped it without.

## The wallpaper picker shows you what you are choosing

0.2.1 put 144 wallpapers behind `Super`+`W` and identified each one by name
alone — and a Steam Workshop name is whatever its publisher typed, so the list
was full of rows called "Nezuko", "final2" and ".". **There is now a preview
pane** beside the list, so highlighting a row shows the wallpaper before you
commit to it. Animated GIF previews render too, which matters more than it
sounds: 62 of the 139 Workshop previews are GIFs, and without that nearly half
the list previewed blank.

**Highlighting a wallpaper no longer applies it.** On 0.2.1, arrowing through
the list ran the full apply on every keypress — which stopped and restarted the
Wallpaper Engine renderer once per arrow key, and quietly persisted whichever
row the highlight last crossed as your choice, even if you pressed `Esc`. Under
"All monitors" it also discarded every per-monitor wallpaper you had set. Now
only `Enter` commits, and closing the panel puts back what you had.

## Audio-reactive wallpapers that said "not a wallpaper"

Fourteen Steam Workshop subscriptions showed up in the picker as dead rows
labelled *"preset (not a wallpaper)"*, and most of them looked like exactly the
audio visualisers you would want.

They are presets — Wallpaper Engine's name for a saved set of knob positions for
some *other* wallpaper, rather than a wallpaper in its own right. Handing one
straight to the renderer draws nothing. **They now render**, resolved to the
wallpaper they configure plus the settings they save, which is what Wallpaper
Engine itself does with one.

Making that safe meant **one renderer process per monitor**. Wallpaper Engine's
setting overrides are not scoped per screen — they land in a single pile applied
to every wallpaper loaded — so a preset chosen for one monitor would have bled
its colours and sizes onto the others. A side benefit: changing the wallpaper on
one screen no longer stops and restarts the wallpaper on all of them.

Editor asset packs still show as unusable, because they contain no wallpaper to
render, and so does a preset whose underlying wallpaper you are not subscribed
to — the picker now tells those two cases apart instead of failing silently.

## Chibi starts

**Chibi crashed on launch on 0.2.1** — on the live ISO and on a fresh install
alike. She was missing four libraries: `sdl2_ttf`, `sdl2_image`, `sdl2_mixer`
and `portmidi`, which the bundled pygame links against but the package never
asked for.

The reason it got as far as a release is worth knowing if you package Python:
pygame does not fail when those are absent. It catches the import error and
quietly substitutes a placeholder module, so everything loads and nothing warns
— until the first frame asks for a font, at which point the whole app dies. The
one library that *was* present, SDL2 itself, made the gap look closed.

The package now checks this at build time instead of at yours: every bundled
extension has its libraries resolved against the declared dependencies, and the
build fails naming the missing package.

## Chibi is a window you can close

**Chibi opens in a normal window**, with a titlebar, and draws her own quit
button besides. `F11` toggles fullscreen if you want the old kiosk behaviour
back.

Previously she came up fullscreen, which under Wayland means no titlebar and so
no close button — `Esc` quit, but nothing on screen said so. A quit button had
in fact been written for this months ago; it landed in a copy of the app that
nothing on Linux runs, so neither the desktop nor the ISO ever saw it.

## Reboot, Shut Down, game mode and the AI backend row

**On an installed system, none of these did anything.** Not silently
half-working — nothing at all, with no error:

- **Reboot** and **Shut Down** in the start menu, since v0.1.0
- **Game mode** (`Super`+`G`) freeing the GPU, since v0.1.3
- The **AI backend** row switching synapd between GPU, CPU and off, since v0.1.7

All three run one privileged command through a passwordless `sudo` rule, and all
three rules were being overridden by the general one that asks for a password.
`sudo` reads `/etc/sudoers.d` in alphabetical order and the *last* matching rule
wins, not the most specific — so `wheel` came after `power-menu`,
`synapd-gamemode` and `synapd-backend`, and quietly cancelled all three. The
rules were present and looked correct the whole time. They are now named so they
sort last.

**Booting from the USB was never affected**, which is much of why this lasted so
long: the live environment runs everything passwordless, so the live ISO always
worked and only installed systems were broken.

Existing installs stay broken until reinstalled — or rename the three files
under `/etc/sudoers.d` with a `zz-` prefix.
