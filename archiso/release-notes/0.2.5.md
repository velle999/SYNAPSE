The installer release. Every previous ISO gave you one layout — ext4, GRUB, a
single root filling the disk — and no way to say otherwise. This one asks.

## Choose your filesystem and your bootloader

**Four filesystems and three bootloaders**, and the installer knows which
combinations actually work rather than letting you assemble one that fails at
first boot.

| | |
|---|---|
| **ext4** | the default; boring in the way a root filesystem should be |
| **btrfs** | the only one with snapshots; zstd compression, `@`/`@home`/`@snapshots`/`@var_log`/`@pkg` |
| **xfs** | fast on large files, cannot be shrunk |
| **f2fs** | flash-oriented |

| | firmware | boots snapshots |
|---|---|---|
| **GRUB** | UEFI + BIOS | yes, via `grub-btrfs` |
| **systemd-boot** | UEFI | no |
| **limine** | UEFI | yes, via `limine-snapper-sync` |

The choices interact, and the installer works the interaction out for you: with
encryption, systemd-boot and limine keep the kernel on the EFI partition so
nothing needs a separate unencrypted `/boot`, while GRUB does — GRUB cannot open
an `argon2id` LUKS2 volume, and weakening the KDF to suit the bootloader is the
wrong trade. The ESP is sized for what will land on it: 512 MiB for GRUB, 1 GiB
for systemd-boot, and **4 GiB for limine with snapshots**, because that one
copies every retained snapshot's kernel and initramfs onto the ESP.

## Bootable snapshots

On btrfs with GRUB or limine, `snapper` takes a pre/post pair around every
`pacman` transaction and the boot menu grows entries for them. A bad upgrade
becomes a reboot rather than a rescue USB.

Timeline snapshots are **off** and the pacman ones are capped — hourly snapshots
kept forever is how a btrfs system quietly fills its own disk.

## ADVANCED: partition it yourself

A third install mode beside ERASE and ALONGSIDE, for the layouts an automatic
one will not generate — a `/home` you want kept, an ESP that already has another
OS's bootloader on it, a partition left over from another distro.

It runs a partition editor on the disk, re-reads the table, and asks which
partitions to use for root, EFI, `/boot` and swap. **Only the partitions you name
are formatted**, it never writes a partition table of its own, and an existing
FAT ESP is kept unless you say otherwise. Every answer is checked before it is
used: a whole disk given where a partition was wanted, something already mounted,
anything on the live USB, or a root too small are all refused with the reason.

## Swap, and zram everywhere

**zram is now set up on every install** — compressed swap in RAM, half of RAM up
to 8 GiB, zstd. No partition needed, which is why it applies to every layout.
Until now this installer made no swap of any kind, so a small machine running a
7B model alongside a desktop had no cushion at all and the OOM killer reached for
the AI daemon first.

A **real swap partition** is offered on the ADVANCED path, for the two things
zram cannot do: hibernate, and add capacity that is not itself RAM. Where both
exist zram takes priority and the disk is overflow. An existing swap is not
re-made by default — `mkswap` changes its UUID, which is what another installed
system's `fstab` and hibernation `resume=` point at.

## The installer asks before it writes, and answers only what you typed

- **A plan review.** Disk, mode, firmware, filesystem, bootloader, separate
  `/boot`, encryption and snapshots are read back before anything is written, and
  answering *no* starts the questions over. Until now the only way to correct a
  mistyped answer was to abort a half-finished install.
- **The package selection is confirmed too**, and re-askable.
- **Prompts no longer answer themselves.** A key pressed during `pacstrap` used
  to sit in the terminal buffer until the next prompt consumed it — so the
  "what to install" menu could be drawn and answered in the same frame, and the
  installer reported a choice nobody made.
- **`ext4`, `xfs` and `f2fs` now say why snapshots are not offered** instead of
  silently skipping the question.

## kitty is the default terminal

Faster, GPU-accelerated, and themed to match. **foot stays installed as the
rescue terminal** — 793 KiB against kitty's 65 MiB, and it renders on the CPU
where kitty needs working OpenGL, which matters in a VM or when a driver has just
broken. Existing installs keep whatever they already had; nothing rewrites your
`synuirc` on upgrade.

## Fixes

- **Installs are verified as bootable, not just written.** Every file a boot
  entry names must exist on the ESP, and the firmware must actually have an entry
  pointing at the install — an ESP that is perfect but unregistered boots the
  install media again and looks exactly like an install that never happened.
- The fallback boot entry named an initramfs that Arch's `linux.preset` has not
  generated for some time. It was a menu item that could only fail; it is gone.
- **limine + snapshots worked end to end for the first time.** Three separate
  faults, each of which reported success: `snapper` was never configured, the
  `limine.conf` layout was one the sync tool rejects, and the initial sync ran
  where it could not work.
- The updater's window no longer asks for a password it has no way to prompt for.
- The transparency slider reaches kitty on systems that never had a `kitty.conf`.
- Tray menus open where their icon is, not where it used to be.

## Testing

`syn-install` now has an end-to-end test that installs SynapseOS in a VM and
then checks the result from outside it — including reading the firmware's own
boot choice off the serial console, so "does the install actually boot" is a
pass/fail rather than a hope.
