SynapseOS gets a photo and video editor.

**Studio** is new in this release: a darkroom for photographs and an edit suite
for video, built around one colour engine so a still and a frame of the same
footage graded the same way come out the same by construction. It went from
nothing to a shipping application over this cycle, and it is most of what is
here — 33 of the 69 commits.

The rest is the desktop getting more usable with a keyboard and a mouse, three
bugs that only appear after you have been running the machine for a while, and
a firewall rule that had been quietly breaking Waydroid on every stock install.

## Studio — one colour engine, two faces

The point of building this rather than assembling four programs is that the
develop stack is the only place a pixel's colour is decided. The video side
does not reimplement it: a clip's grade is baked to an Iridas `.cube` and handed
to ffmpeg's `lut3d` filter, so the photograph and the frame travel the same
arithmetic.

That claim is measured rather than asserted. The suite renders an image through
the engine, bakes the same settings to a 33-node LUT, has ffmpeg apply it, and
compares the two. It fails under 45 dB PSNR. A 65-node LUT measures *worse* than
a 33-node one, which is how we know what is left is quantisation and not
interpolation error.

**The darkroom** is the face that ships. 64 develop settings described once in C
and driving the command line, the sidecar and the GUI panel together. White
balance, exposure, tone regions, contrast, curves, HSL, split grading and
vibrance are pointwise and live in the shared stack; clarity, texture, dehaze,
sharpening, noise reduction, vignette and grain need a neighbour or a coordinate
and map to an ffmpeg filter on the video side instead. Two colour domains:
linear for the light physics, sRGB-encoded for the look controls.

Edits live in a `<file>.synstudio` sidecar and **the original is never written**.
The tests md5sum the source photograph before and after to prove it — an editor
whose test suite could modify a real photograph would be the most dangerous file
in the repository.

**The edit suite** is real and tested and still reached from the command line,
which is why the menu entry claims only Graphics. What is in it:

- **Cutting.** Undo, markers, snapping, multiple selection, copy/paste/duplicate,
  and `paste --grade` to put one clip's look onto another — or onto every clip on
  the track, which is what grading a scene actually looks like.
- **Linked audio and video**, so moving a shot takes its dialogue with it. A link
  is a group id rather than a pointer to a partner, because a shot, its dialogue
  and its room tone is three things and an index does not survive the clip beside
  it being deleted.
- **Sixty transitions**, a dip through a colour, and sound that crosses with the
  picture.
- **Retime and a stabiliser**, titles and subtitles, an effects stack with a
  format so effects can be somebody else's, and voiceover recording.
- **The sound chain**: noise reduction, a gate, six bands of EQ, a compressor, a
  de-esser, fade shapes, delivery loudness and ducking. The order is the design —
  clean it, shape it, control it — and a test asserts that order as positions in
  the graph, so a reshuffle that still contains every filter fails.
- **Track automation**: a fader ridden against the picture, sharing the clips'
  interpolation and eases.
- **Scopes** — waveform, RGB parade, vectorscope — computed here rather than by
  an ffmpeg filter, because a scope is read to decide whether two shots match and
  an answer produced by a different renderer is an answer about something else.
- **Shot match**, fitted rather than solved: each control is set, rendered through
  the real engine, measured and bisected, so it never needs to know what
  `contrast` means. On a realistic pair, 22.5 dB apart before and 33.1 dB after.
- **Log input transforms** (`slog3`, `vlog`), applied before anything else reads a
  pixel, so footage shot log stops arriving flat and washed.
- **Delivery**: a render range, seven presets named for where they are going,
  burn-in for review copies, image sequences, and a render queue that is a file of
  commands rather than a daemon.
- **Versions** — a document you decided to keep, with a name you chose, that
  nothing expires — and a watermark.

**ffmpeg, ffprobe and dcraw_emu are subprocesses, never libraries and never a
shell.** A shipped component that linked ffmpeg stopped launching the day ffmpeg
bumped a SONAME, on an ordinary upgrade, with nothing the application could do
about it. A pipe has no ABI. It also means a photograph called `; rm -rf ~` is
just a photograph with a strange name.

586 assertions, all headless — no display, no compositor, no GPU — and clean
under ASan, UBSan and LSan.

### One bug in there is worth naming

`apply_contrast` is a cubic that is a contrast curve on [0,1] and a cliff outside
it. Anything that lifts a highlight past white leaves a value above 1 in the float
pipeline, and the cubic then returns a large negative number, so every channel of
that pixel gets multiplied by it:

```
exposure=8 contrast=0  ->  255 255 255
exposure=8 contrast=5  ->    0   0   0
```

Five points of contrast turned white into black. It had been there since the
develop stack was written and it took the shot matcher walking into it to find it.

## The desktop

**One press that turns off everything you can see through.** Appearance ▸ *Make it
all solid*. Switching the effects off by hand was three controls and the third was
invisible until it bit — a bar or dock you had ever nudged pins itself and stops
following the master, so it stayed exactly as clear as it was on a desktop whose
one glass control read "Off". Writing the test found the second half: Glass at Off
was never opaque anyway. The curve hands the bar and the dock 0.95 at the bottom of
the slider, so somebody could turn every switch off and still see wallpaper through
their dock. The action sets both outright.

**SYNAPSE Prism, in daylight.** Prism is the house theme and the only one a fresh
install has ever booted into, and it is dark — so a desktop that wanted a light
file manager and light browser chrome had to leave the house theme to get it.
`prism-light` is the same theme with the surface inverted and deliberately nothing
else changed: the same glass, the same accent measured off the wallpaper. Two
things could not simply be inverted — the fallback accent measures 1.7:1 on a
near-white panel, so it drops four stops to the same hue at 5.0:1, and the surface
is `#EEF1F6` rather than white so the contrast correctors have somewhere to work.
Dark Prism stays the default.

**Our own app icons follow the theme accent.** Nine violet tiles in a bar that was
not violet anywhere else read as a house style against SYNAPSE's cyan and as an
oversight against Gruvbox's orange. The recolour is careful about two things: it
does not repaint somebody else's icon (the gate is a name *and* a content test —
`syn` is a prefix syncthing, synfig and synergy also answer to, and Resolve's
clapperboard is Resolve's branding), and it does not erase the teal detail on the
slider knobs and pad bars, whose meaning is carried by *not* being the brand
colour.

The first cut of that shipped a set of highlighters on a green accent. HSL's L is
a channel average and not a brightness — green carries five times the luminance of
blue at the same L — so held at the violet's lightness the family came out 30
points of CIE L\* above it on a yellow-green accent. It rotates in OKLab now, where
L is perceived lightness, and chroma is scaled by the accent's own: following a
theme is not only wearing its hue, and an icon that keeps the violet's chroma on
Nord's deliberately quiet frost blue is a poster pinned to a muted desktop.

**The mark picks its colourway off the ground it lands on.** The dendrite logo
ships in one colour and lands on two kinds of surface: the violet cut measures
about 7.2:1 on a dark panel and 2.4:1 on a pale one, where it stops being a logo
and becomes a smudge. On prism-light that was visible in three places at once —
the start button, the welcome panel header and rofi's menu — each beside text that
does follow the theme. Each caller now asks the thing it already measures.

**One sharp logo wallpaper instead of two soft ones.** Both were rasters too small
to be wallpapers — 1254×1254 and 1402×1122, square and 5:4, on a 16:9 screen.
There is a vector master now, so the picker carries one entry rendered at
3840×2160.

**Turning off the bar turns off the bar.** Control panel ▸ Desktop ▸ Bar did its
work by killing the process — and that process is not only the bar. The desktop
widgets, the OSD, the start menu, the volume mixer and the post-it notes are all
windows of the same shell, so asking for the strip across the top to go away took
the visualiser, the big clock, the notes and Tux with it, with nothing on screen
connecting the two. The bar honours the setting itself now and unmaps one window,
which is also what hands its reserved strip of screen back. The stop and start
commands remain for a waybar desktop, which cannot be asked, and are empty by
default. It also means the setting survives a login for the first time: the row
always wrote the answer down, but nothing read it back, so the session's own
autostart line put the bar straight back at the next boot.

## Getting around

**Super+Space is the command bar again.** It is what this desktop is for and it
should be on the biggest key on the keyboard. rofi keeps everything else it gained
and moves to **Super+=**. The niri column moves stay on Super+, and Super+. — the
keys niri itself uses — after a first attempt pushed them onto the brackets and
made the wrong half of the trade.

**The start menu walks with the arrows.** Right descends into a category and Left
comes back out, and Right is deliberately *not* a second Enter: on a leaf row that
would launch the thing, which is far too much to hang off an arrow key pressed
while looking for the next level down. It also stops losing your place — the
highlight comes back to the category you were just in, matched by page id rather
than by a remembered index, because a search or a renamed category moves the rows.

**The welcome menu (Super+Escape) grew a mouse**, a visible way out, and honesty
about the keys. Its key column was eighteen hand-typed strings that stopped being
true the moment a bind moved — the menu that exists to answer "what are the keys"
was answering with the wrong one. It reads the chords out of the live bind table
now, so it is also right for anyone who rebound something. "Show At Startup" moved
out of the middle of the list, where Enter meant "tick" while every neighbour meant
"go", and became a *Don't show again* checkbox in the corner. Appearance joins the
list, since the theme manager was reachable by a key nobody would guess.

**Right-click in the task manager** — End task, Force quit. Both were already there
on `x` and `X` behind a confirmation that names the pid and refuses init and synui
itself; `taskmgr_click()` opened with `(void)button;`, so a right-click was a
left-click and the two most useful things in the panel were keys or nothing. Both
items arm the existing confirmation rather than signalling, so the menu inherits
every refusal.

**Super+arrows move the focused window.** On a floating desktop — and for any
floating window on a tiled one — it slides 40px. A tiled window moves through the
layout instead, because a tiled window has no position of its own to slide. They shipped on Super+Shift+arrows earlier in this cycle and
lost the Shift before release: it was held back for a keyboard snap that does not
exist, while snapping here is something you do by dragging a window to an edge.

**The emoji picker's category strip takes the mouse**, and is two lines now — it
drew as many tabs as fitted across and dropped the rest, which cost Symbols and
Dingbats. Survivable while Tab was the only way to reach them; not survivable once
a tab is a click target.

## Holding an update back

`synpkg ignore <package>` stops a package being upgraded, `unignore` releases it,
and `synpkg ignore` with no arguments is the list — with the version each hold is
refusing, because a hold whose cost you cannot see is a hold nobody revisits. The
GUI gains a **Held back** page and a quiet Hold button on every pending update.

**The list is pacman.conf's `IgnorePkg`, not a synpkg file.** An ignore only this
program honoured would be a lie on a machine that also has pacman on it. Three
package systems means three mechanisms — `IgnorePkg` for repositories and the AUR,
`flatpak mask` for Flathub, and a third state in syn-update's manifest for
SynapseOS components, which pacman's IgnorePkg does not gate — but one listing,
because "what am I holding back" is one question and the person asking it does not
care which file the answer lives in.

**Held is marked, never hidden.** Filtering held rows out of `updates` is the
obvious reading of "ignore" and it is the wrong one: the reason for a hold is
almost always temporary, and a list that silently omits them is how a package stays
pinned for a year. They are listed, dimmed, labelled, and left out of the count and
the download size.

Two things that had to be fixed for it to be true rather than merely configured:
the AUR upgrade pass is our own loop over `makepkg -si` and was enforcing nothing,
so an AUR package you held back would have been rebuilt and reinstalled by the very
command you configured to leave it alone; and syn-update's manifest writer
recomputes the whole file from `pacman -Q`, which can only see installed-or-not, so
a held component was written back as `selected` and the hold evaporated on the
first successful apply.

**Enable Flathub failed on exactly the machines it is for.** Pressing it opened a
terminal that printed `flatpak is not installed` and exited — the button reported
its own precondition and did nothing about it. It installs flatpak now, saying so
first. Both that button and Enable BlackArch could also be hovered but not clicked:
the results list is declared after the empty-state block and covers the same rect,
and a Flickable takes the press across its whole area whether or not it drew a
single row. The one state those buttons exist for is the state with no rows in it.

## The installer

**Offline is found out at the start now, not at the end.** syn-install downloads
the base system and has always checked before touching a disk — but the graphical
window never did, and it writes `wifi_picker=no` into the profile because it
cannot draw nmtui, which turns the script's patient retry into an immediate exit.
So installing without a connection meant filling in every page, pressing Install,
and watching the window vanish with all of it. The same probe now runs when the
window opens, with a banner, a Re-check, and a button that opens synui's own
network panel.

**Tab and the arrows walk the whole window.** There was no keyboard navigation at
all outside the package picker. The arrows *move* rather than change a value —
these pages mix single choices, checkboxes and buttons in one column, so "the next
thing" is the only meaning that holds for every control. The username, password
and hostname boxes needed opting in specifically: a `TextInput` does not take tab
focus by default, so the three things a keyboard user most needs were the three
Tab could not reach.

**The desktop no longer falls to headless and stays there.** Untick the compositor
and re-tick it, and the desktop sat on "None (headless)" with the SynapseUI row
enabled and unchecked, as if headless were the default, with nothing saying it had
moved.

**A flatpak route**, because LocalSend is in no official repo and Space Cadet
Pinball is in no repo and no AUR package but a `-git` one that compiles during the
install. Both are **Full-only**: the first flatpak drags the freedesktop runtime
with it, so putting them on Standard meant every ordinary install grew several
hundred megabytes and the longest step in the run to get a file-sharing tool and a
pinball game nobody had asked for by name. Custom offers both as ticks.

## Things that only break after a while

**A terminal shrink was destroying the rows it dropped.** Dragging a syntty window
narrow and wide again came back with the top of the screen gone — not scrolled
away, *gone*, and not in the scrollback either. The rows a shrink drops off the top
were being freed; they are the oldest text on the screen, which is precisely what a
scrollback is for. A single drag delivers several hundred sizes and does not stay
near the window's resting size on the way, so one pass through a short window
destroys the whole screen. It only bites on the way down, which is why it looked
intermittent.

The tests did not catch it because every assertion in that section reads the
*screen*, and the loss is only visible in the *history*. "Shrinking keeps the
bottom" passed against a build that was destroying the top.

**A terminal stopped taking keystrokes after a suspend.** A seat loses its keyboard
on every session disable, which is to say on every suspend. syntty's capability
handler only ever *added*: the proxy stayed non-NULL, so when the bit came back on
resume the guard was false and the keyboard was never re-bound. The window took no
keystrokes again for the rest of its life — no error, no log line, and a pointer
that still worked, so it read as a hung terminal rather than a lost input device.

**Nothing dragged out of the file manager any more.** Qt 6.11.2 landed two days
before this release and `Drag.active = true` stopped starting a system drag:
the assignment returns straight away, no `wl_data_source` is ever offered, and
nothing says so. A row onto a folder, a pane onto the other pane, a file onto mpv —
all silently dead. Fixed against both Qt versions, guarded on the behaviour that
tells them apart rather than on a version test.

**Waydroid had no network on a stock install, and the firewall was why.** synnet's
input chain is default-drop and trusts anything from a private range — once the
guest *has* an address. The packet that asks for one is sent from 0.0.0.0 to
255.255.255.255 and matches no accept, so the drop policy eats the DHCPDISCOVER.
The container runtime's own rule does not rescue it: it lands in a different
nftables base chain, and a packet traverses every base chain on the hook, so two
firewalls compose as the stricter of the two. `/etc/synnet/trusted-ifaces` now
names the bridges this box is the gateway for, and each gets DHCP-server and
DNS-server accepts — the gateway services only, not the interface wholesale, since
an addressed guest is already trusted and opening every host port to whatever an
Android APK runs would add nothing but risk. Settings ▸ Network lists them.

**The boot splash was never selected.** The live ISO booted to the manufacturer's
logo and then Arch's, with a SynapseOS plymouth theme sitting on the image doing
nothing. Everything except the choice was already right — the package, the hook,
`splash` on all three cmdlines, the theme itself. What was missing is the one file
that names the theme, so Arch's `Theme=bgrt` won and drew the firmware's logo
exactly as designed. Never being named, the theme was never copied into the
initramfs at all. Installed systems were unaffected; this is the live image only.

**Dragging a dock icon was laggy.** Moving the icon repaints the dock canvas on
every output for every pixel travelled, and each repaint was rescaling every pinned
icon from its decoded size down to the 48px cell with an expensive filter. Each
icon is scaled once and kept now — with a generation counter, because the accent
retint repaints the pictures inside the cache and hands back the same pointer.

**`fetch` said the operating system where the window manager goes.** The row read
`WM: SynapseOS`, which is the desktop name the session exports, not the compositor.
There are two rows now and each is discovered rather than read out of an
environment variable.

## Under the hood

CodeQL had been hitting GitHub's six-hour job ceiling on every push to main. It
was never slow at extraction — it finished 54 of 61 C/C++ queries in about a
hundred seconds and then one ran until the job was killed. It builds the code and
traces the compiler now instead of guessing at types and include paths, which is
both more accurate and, for most of those queries, far faster. Seven range-analysis
queries still did not terminate on a properly traced database, so they are excluded
by id with the measurement recorded beside them rather than the theory.

Studio joins CI, which had never built or tested it anywhere but a developer
machine. The "every meson source is tracked" guard now runs over every component
with a `meson.build` rather than the five CI compiles — a guard that exists for
exactly one failure, which had just happened for real and shipped in two releases:
a commit staged `meson.build` and swept in a line naming a file that was not
committed, so the tree could not configure on any machine except the one where the
file existed untracked.
